# Memory research scan and adversarial triage (2026-11-12)

Window: 2026-10-13 to 2026-11-12. Sources: MEMOIR (2611.07631, 5 Nov), Pro-Memory (2611.05731, 3 Nov),
transparent-compact (2610.20116, 14 Oct), AgingBench v2 (2605.26302, revised 7 Nov; abstract only).
Method: ideas ranked, the top three each attacked by an independent read-only reviewer against the code.
The `/last30` and `/adhd` skills named in the routine were not installed in the session, so the scan and
the ideation were done by hand with web search.

What the papers add:

- **transparent-compact.** Model-written summaries rarely lose a rule outright. They reword it: narrow its
  scope, record a standing rule as a fact about one past task, or *keep a decision the user had reversed*.
  All nine such failures were confident ones. Declaring what was removed turns them into abstentions.
- **MEMOIR.** Screen for preservation before a merge discards anything (0 losses in 100 audited merges);
  revise a memory's priority from whether it was used, not from a score fixed at write time.
- **Pro-Memory.** Pending intentions carry an optional activation condition, ONCE/RECURRING, and evidence
  links. Without evidence links false alarms more than double; without one-shot retirement completed
  intentions re-fire.

## Shipped: resurrection guard

Every dedup layer and the ledger block shown to the extractor saw active entries only. A reviewer's probe:
a user decision "Use MongoDB…" superseded by the user, then restated in assistant-only text, came back as a
new active entry. It kept a narrow falsifier (`psycopg`) that would hard-deny the user's new choice, was
re-pinned under the "not overridable" header, and then swallowed the user's "Never use MongoDB…" as a
duplicate.

Now `Entry.revoked_by` records who superseded or retired an entry (set from the event, so a replay backfills
it). `LedgerStore.revoked_by_user()` returns the tombstones: revoked entries that had user authority or
that the user revoked. In `Extractor._apply`, after active dedup, a candidate that restates a tombstone
(same normalized text, or word-set paraphrase with the same polarity) is dropped and logged as
`resurrection_blocked` unless it is user-sourced and its evidence is not contradicted by the user turns.
Entries the agent revoked itself are not tombstones, so the agent can re-make its own decisions.
`orphaned` and `unknown_current` entries are not covered.

## Shipped: polarity-aware dedup

Word-set Jaccard at 0.8 scored "Never use Postgres for the session cache and job queue storage" at 0.91
against the positive statement, so a reversal that the extractor emitted as an entry was skipped as a
duplicate, and `ledger dedupe --apply` could supersede it. `schema.has_negation` is a crude polarity test;
text dedup, embedding dedup, tombstone matching and `duplicate_groups` now require it to agree. The cost of
a wrong answer is one extra entry.

## Why I5 was not built as proposed

`evidence_supported` is bag-of-words overlap, not an endorsement test. The reviewer ran it: a question
("should we use Postgres for the cache?"), a negation, and the user quoting the agent all return True.
Automatic promotion would make the extractor model the sole judge of a hard-deny entry. Revisit only with
contiguous-substring evidence from the typed prompt, a question and negation guard, and ~90% precision on a
labeled set (the bar set for `possibly_invalidated`).

## Specified next: revoked decisions in the pin block

Extractor and `SUPERSEDE`-line supersessions pass `new=None`, so when no replacement was extracted nothing in
context says the decision is dead. Accepted spec: a trailing section after the active entries (so it stays
out of the `MEMORY.md` mirror), compaction path only and persisted so later `write_pinned` calls keep it,
user-revoked entries only, at most 3, only those with an anchor hit in the summary, 100-character
statements, formatted `D-0001 (revoked <date>, replaced by D-0007 | no replacement)`. Open risk: listing a
revoked decision may prime the agent to follow it, and an anchor hit also fires on a summary that correctly
says the decision was dropped. Measure `resurrection_blocked` counts first; build this if they are nonzero.
