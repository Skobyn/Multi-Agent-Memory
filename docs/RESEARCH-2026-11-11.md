## Shipped: a revoked entry leaves the pin block when it is revoked

`write_pinned` ran from CLI commands, the MCP supersede tool and `PostCompact`, but not from the hook paths that
change the ledger during a session: `SUPERSEDE` lines at `UserPromptSubmit` / `Stop` / `SubagentStop`, and the
extractor's supersede events. A reviewer reproduced it: after both entries of a ledger were superseded in
conversation, `pinned.md` and the mirrored block in `MEMORY.md` still listed them under "not overridable by
conversation", and the startup briefing stays silent when nothing is active, so the stale block stood alone. The
background workers refreshed only when an extraction added entries.

Now `LedgerStore.dirty` is set by any recorded event, `hooklib.run` refreshes the pin block after a handler that
left it set, and the background workers refresh on the same flag. A refresh between compactions keeps the last
audit's `[re-pinned: dropped by compaction]` marks, logs nothing, and writes each file atomically and only when
its content changed (measured cost about 1 ms for 62 entries).

## Shipped: role labels the transcript cannot forge

`format_turns` flattened turns to `[user <uuid>]: text` lines, which is the serializer the paper attacks. Assistant
text that quotes a fetched file, or a multi-line shell command, could put its own `[user 7f3a]: ...` line in the
label column; a reviewer confirmed that such an entry was stored with user authority and kept a `**` falsifier.

- Turn bodies are indented (`  | `) and tool briefs are one line, so only the serializer can write a label in
  the first column. This is the deterministic part. A per-call nonce was dropped as redundant with it.
- User-role rows the harness wrote are labelled `[injected <uuid>]` and cannot grant user authority: `isMeta`
  rows (previously shown as `[user ...]`), rows whose `origin.kind` is `peer` or `task-notification`, and text
  that opens with a harness envelope. A routine's stored prompt (`subkind: scheduled-trigger`) stays a user
  turn. Unknown `origin` kinds stay human, as the reader fails open everywhere else.
- Demotion is narrow: a `source=user` claim becomes `agent` only when its quote is unsupported by the human
  turns and matches text behind a `[user ...]:` look-alike in a turn the user did not write. A plain mismatch
  stays warn-only (the 32cd3c0 decision), because "ok go ahead" after an assistant proposal is a real user
  confirmation whose quote sits in the assistant turn.
- A harness envelope arriving as a prompt applies `SUPERSEDE` lines with agent authority.

What this does not cover: text the user pastes into a real prompt is user text by definition, and an assistant
that relays injected content without a label look-alike still reaches the extractor model as assistant text,
where the model's `source` judgment and the warn-only check are all there is.

## Not built: `ledger verify`

The join key is empty by construction. Prompt-time extraction builds its turns with `uuid=""`, the later full
pass drops the entry as a duplicate without backfilling, and transcripts are archived only at `PreCompact` and
`SessionEnd`. Where it could run it would mark the real threat (a pasted document) as verified. What survived is
the write-time record: `extracted` now carries `evidence_check`, and `evidence_unverified` and the new
`forged_user_source` records name their entry, so a later listing can join them without archives.
