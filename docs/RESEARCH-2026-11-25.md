## Shipped: a falsifier counts what the change adds (A)

The reviewer reproduced the false deny with the real `GatePipeline`:

- The user constraint forbids `import pymongo|MongoClient`, and `src/db/client.py` already contains both. A Write that
  only adds a docstring to that file was **hard-denied**, because `diff_regex_forbidden` searched the whole new
  content. An Edit was denied too, because its `new_string` kept the legacy line as context.
- Those denies spend the **session** deny budget. After five of them, a real `eval(` violation of a different user
  rule came back advisory ("deny budget exhausted").
- Fixing Tier 0 alone was not enough. Tiers 2 and 3 received the whole new file labelled `"diff"`, so a model could
  still flag the legacy line.

What shipped (`gate.py`):

- `Change` carries the pre-images: each `(old_string, new_string)` pair for Edit and MultiEdit, and the file on disk
  for a Write that overwrites one (read with a 2 MB cap).
- `introduced_matches` counts each distinct matched string in the new text and in the pre-image. The rule trips only
  if a count goes up, so copying an existing violation still trips (2611.11455). The check runs per edit, so a
  MultiEdit whose second `old_string` contains a match that its first edit created still trips. An unreadable or
  oversized pre-image falls back to checking the whole text, as before. The trip names what was added
  (`+1 'MongoClient'`).
- Tiers 2 and 3 get `Change.diff_text()`: a unified diff when the pre-image is known.
- Bash, NotebookEdit and `diff_regex_required` are unchanged. `diff_regex_required` only checks new files, whose
  pre-image is empty.

Accepted limits, from the review:

- A same-file swap (delete one `MongoClient(a)`, add `MongoClient(b)`) nets zero and passes.
- A violation let through by the deny cap, the budget or `enforce: false` becomes part of the pre-image and is not
  flagged again on later rewrites. A new copy of it still trips.
- Bash keeps its existing gaps: the command text is checked, and `sed -i` records no path.

## Shipped: calibration certifies or abstains (2610.36544)

The P reviewer found that calibration made the gate **more aggressive** on almost no evidence:

- `fit_tau` with 1 conflict and 11 consistent labels returned τ = 0.30, which passed `MIN_LABELS_PER_TYPE = 12`. With
  no consistent labels at all, the false-deny rate defaulted to 0. When no τ met the ceiling, a fallback τ was
  stored anyway.
- `Calibration.calibrated` was one global flag. Once any one type was fitted, the gate dropped its 0.9 floor on
  `p_conflict` for **every** type, uncalibrated ones included.
- 0 false denies out of 11 is consistent with a 24% false-deny rate at 95% confidence. Showing that the rate is
  under the 2% ceiling takes about 149 clean consistent samples.

What shipped:

- `fit_tau` accepts a τ only if the one-sided 95% Clopper-Pearson upper bound on its false-deny rate is within the
  ceiling, and the τ catches at least one conflict. Otherwise it abstains: it returns no τ, gives the reason and the
  sample size needed, and stores no fallback. With no consistent samples it always abstains.
- `calibrate` stores only certified thresholds, and `load_calibration` drops any threshold without `certified: true`
  in its details. A calibration file written before this change is therefore ignored until `calibrate` runs again,
  and the defaults apply meanwhile.
- The gate lifts the 0.9 floor per entry type (`Calibration.is_calibrated(type)`), both in the no-advisor path and
  in `_held_user_flags`.

## Specified next

- **O: path scope follows a move.** Confirmed hole: after `git mv src/db lib/db`, an Edit adding `import pymongo` to
  `lib/db/x.py` is allowed, because `run_tier0` skips out-of-scope entries and the falsifier never runs. The reviewer
  showed that `classify` cannot parse moves (`-t`, quoted paths, multiple sources and `cd` all go wrong). The shape
  that survived:
  - a dedicated `shlex` parser for `mv` / `git mv` that gives up when a command is ambiguous;
  - an append-only `scope_alias` event built by prefix substitution, only for destinations inside cwd, never for
    permissive entries, and accepted by #33's `_weakens_user_entry` only as a strict superset;
  - a note to the agent, plus a line in the briefing.

  It waits on #33. The reviewer listed ten required tests.
- **P (shrunk): dedup must not swallow a revision.** `_text_near_duplicate` (Jaccard ≥ 0.8) dropped "timeout … 30
  seconds" → "… 60 seconds" as a duplicate, so the old value stayed enforced. A candidate whose numbers or key=value
  values differ from its match should not count as a duplicate. A shadow `value_divergence_candidate` log belongs
  with the unbuilt `possibly_invalidated` work. It must never change an entry's status: an agent entry sharing a key
  would otherwise demote a user rule.
- `quantile_threshold` is fitted but never read by the gate.
