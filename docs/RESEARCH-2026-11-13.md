## Shipped

- **Supersede cascade respects the authority rule.** An agent supersession of its own entry used to move every
  same-scope entry to `unknown_current` and every dependent to `orphaned`, user entries included, which drops
  them from the gate and pin block. That is the MemoryDojo pattern exactly: poisoned text persuades the agent
  to "supersede" something, and a user constraint silently stops being enforced. Now the cascade skips
  user-authority entries unless the supersession is `by=user`, and logs them once as `cascade_skipped`.
  Replaying older event logs now leaves those entries active (the safe direction).
- **`resolve --retire` needs `--by user` for user-authority entries** (store and CLI; default `agent`). Before, an
  orphaned or unknown_current user entry could be retired by anyone, so the cascade above chained to permanent loss.
- **`retire --provenance user` is refused** (retire user entries by id). One Bash call could otherwise wipe them all.
- **`dedupe --apply` keeps the user-authority entry** of a duplicate group instead of the earliest id, so a merge
  never supersedes a user rule into an agent one.
- **Drift skips confirmed premises** (`Entry.user_authority`, not `source == "user"`).

## Specified next (not built)

1. **Agent-run CLI with user authority (highest).** The agent has Bash, and `/ledger` runs the CLI through the
   agent, so `ledger confirm`, `add --user` and `--by user` are only as trustworthy as the agent. The only guard is a
   prose line in `commands/ledger.md`. Proposal: a Tier 0 check in `pre_tool_use` that denies a Bash call invoking
   `em-hook ledger` with `confirm`, `--user` or `--by user` unless the latest real `UserPromptSubmit` prompt
   names the same subcommand and id (the user typed `/ledger confirm D-0007`). Needs a check of what the
   UserPromptSubmit payload contains for slash commands before building.
2. **`SUPERSEDE` lines inside pasted prompt text** are applied with `by=user` (fences are stripped only for agent
   text, `hooks.py` `_apply_supersede_lines`). Strip fenced and quoted blocks for user text too, and require the
   line to start the prompt or a line outside a fence.
3. **Prospective commitments, shadow only** (idea B, shrunk): a `command_requires_followup {pattern, followup_pattern}`
   falsifier, Bash only, user-authority entries only; a per-turn `turn_tool_log` (reset on UserPromptSubmit, with an
   `ok` flag from PostToolUse); at Stop, log `followup_missing` when a successful trigger has no later follow-up.
   Block only behind `gate.followup_enforce` (default off) and only if the turn check did not already block. Add a
   bench scenario ("after every migration run `alembic current`") before enabling.
4. **Recorded, not changed:** an extractor `source=user` entry whose evidence fails `evidence_supported` is kept and
   logged (`evidence_unverified`), by the earlier decision that demoting a paraphrased real user rule is worse.
   Reconsider if MemoryDojo-style fixtures show relayed text being labeled `user`.
