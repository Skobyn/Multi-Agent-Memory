## Shipped: calibration inputs are the user's (C)

The reviewer showed the whole route through the real `PreToolUse` hook and CLI:

- `authority.check` returned `(None, [])` for `ledger label tuA ok`, `ledger mark-good s1` and
  `ledger calibrate --min-labels 1 --max-false-deny 1`. `selfguard` skips commands that are only ledger CLI calls,
  so the agent's Bash call was allowed.
- **One denied call was enough.** `label` did not deduplicate, so labelling `tuA` "ok" twelve times wrote twelve
  samples. `calibrate` then moved `tau_by_type` for `constraint` and `decision` from 0.75 to 0.9. `--min-labels 1`
  was a shorter route still.
- The same Edit against a user-authority constraint at p = 0.85 was denied at tier 3 before. Afterwards it was
  allowed at tier 2, unflagged, so the advisor never ran. With tau 0.95, constraints at p = 0.80, 0.90 and 0.94 were
  allowed.
- **The damage stops at some tiers.** Tier 0 falsifiers still deny. `process` and `commitment` entries and
  destructive commands always go to the advisor. The first-mutating-write advisor runs once per session. tau cannot
  rise above 0.95. `mark-good` changes nothing today, because the gate does not read `quantile_threshold` yet.

What shipped:

- `label` and `calibrate` are user-only subcommands (`authority._USER_ONLY_CMDS`). They are matched by subcommand
  name, not by widening `_MARKER_RE`, which would have refused `ledger search label`. They run only when the user's
  latest turn contains the exact command, once, as with `confirm`. argparse does not accept abbreviated
  subcommands, so `ledger cal` cannot slip through.
- `calibrate` keeps one label per `tool_use_id`, the last one written. A call relabelled twelve times counts once,
  and relabelling corrects a mistake. The bench and the existing tests use unique ids, so their results do not
  change.
- `mark-good` stays open until `quantile_threshold` is wired into the gate, and then it joins the set.
- Cost: "label the last flag as ok" in plain words no longer works. The user types `/ledger label <id> ok`.

## Shipped: Bash write targets reach path falsifiers (I)

The reviewer reproduced the two-step hole through `run_tier0` and `GatePipeline`. A user rule "Never touch
src/auth.py" with `path_glob_forbidden` gave `allow` for Write `/tmp/fix.sh` (content `rm src/auth.py`) followed by
`bash /tmp/fix.sh`. The Bash call was `unknown/opaque` with no paths, and the path-scoped entry fell out of scope. The
only net was Tier 1 retrieval on the Write's script text, which needs a decision model scoring 0.9 or more.

It also found a bigger hole first. **One-step Bash writes named no path**, so none of these tripped the falsifier:

- No path captured: `sed -i ... src/auth.py`, `perl -pi -e`, `black`, `git checkout -- f`, `git restore f`,
  `patch f < p.diff` and `python3 -c "open('f','w')"`. Their rules had no path group.
- Classified `no_source_write`: `python3 - <<EOF ... EOF` (the rule's `.` did not cross the newline),
  `Path(...).write_text`, `os.remove`, `find -delete`.
- A path was captured but never matched: `rm ./src/auth.py` and `rm <cwd>/src/auth.py`, because Bash paths were
  not normalized.

What shipped:

- `bash_classifier` takes the positional file arguments of `sed -i`, `perl -i`, formatters, `git checkout --` /
  `restore`, `patch` and codemods (`_arg_paths`). It also takes the written path literals of python and node writes
  (`_literal_paths`: `open(..., 'w')`, `Path().write_text`, `os.remove`, `shutil.move`/`copy` destination, `fs.writeFileSync`,
  ...). A read-only `open('f')` is not a write. `py_write`/`node_write` cross newlines, so heredoc scripts count.
  `find ... -delete` is a write.
- `gate.bash_targets` normalizes each path (`./`, `$PWD/`, absolute under cwd, `..`). It also reads the local
  shell scripts the command runs (`bash`/`sh`/`source`/`.` `x.sh`, `./x.sh`), one level deep, at most 64 KB, with no
  NUL in the first 4 KB. Comment lines are dropped, so mentions and commented-out lines do not count. The targets are
  computed once per call (`Change.targets`), and both `entry_in_scope` and `evaluate_falsifiers` use them. A trip
  from a script says so ("written by a script this command runs"). A call whose script writes counts as mutating.
- Killed: the selfguard half. Shell bypasses of the monitor's own files are unbounded by design, and the config
  fingerprint reports a change whatever route made it.
- Not done: python and node script files (`python3 x.py`). That needs a parser, and it waits until literal capture
  has proved itself on inline code.

## Second round: review of the finished diff

A fourth reviewer attacked the committed diff and reproduced seven defects. Each now has a regression test:

1. **Naming a script counted as running it.** The runner was optional in the script regex, so `cat fix.sh`,
   `shellcheck fix.sh`, `git add fix.sh && git commit` and `cp fix.sh ...` tripped the falsifier and counted as
   mutating. A script is now read only when a shell, `source` or `.` runs it at command position, or when it is
   invoked as a path (`./x.sh`, `/abs/x.sh`).
2. **Prose became write targets.** `py_write` matched `python3` anywhere, so a commit message or PR body that quoted
   `os.remove('src/auth.py')` tripped. An interpreter now counts only at command position (after `env`, `sudo`,
   `uv run` and similar). Writes are looked for only inside that command's extent: up to the first unquoted
   separator, or through the heredoc's terminator line.
3. **Excluded paths counted as targets.** `ruff check --fix --exclude src/auth.py src` tripped on the file it skips.
   Value-taking options (`--exclude`, `--settings-path`, `--select`, `-m`, ...) now consume their value.
4. **Branch names counted as paths.** `git merge feature/auth.py` and `git rebase origin/main` produced targets. Git
   targets now come only from after `--`, or from the positionals of `restore`.
5. **Large commands were quadratic.** A 94 KB heredoc took 5.1 s. Each literal scan now covers its own extent once,
   `classify` is cached per command, `open(` scans at most 300 characters, and the interpreter-path prefix is bounded.
   Every pathological input in the tests takes under 0.2 s.
6. **BSD `sed -i ''`** treated the empty suffix as the script. Empty tokens are dropped.
7. **Quoting bypassed the authority check** (a gap that predates this diff, and matters more now):
   `em "ledger" label t ok`, `em led''ger label t ok` and `L=label; em ledger $L t ok` ran with no check. The CLI
   test now also runs on the dequoted command, and a subcommand that the shell computes is user-only.

Also fixed: `ledger feedback` reads labels with the same dedupe as `calibrate`.

Accepted limits:

- Script runs that are still missed: `sh<fix.sh`, scripts without `.sh`, `make`, scripts called from other scripts,
  and a relative script after `cd sub &&` (resolved against the hook's cwd).
- In-place edits missed today: `sed --in-place`, `sed -ie`, `perl -0777 -pi`. Python writes missed: a path held in a
  variable, and escaped quotes.
- Directory targets (see Specified next).
- Importing `epistemic_monitor.calibration` from `python3 -c`, or appending to `labels.jsonl`, bypasses the CLI
  check. A write to the data directory still gets the selfguard advisory and the user-facing notice (11-19).

## Fixed: a handoff no longer presents a superseded rule as binding (A)

The reviewer probed every surface that puts ledger text in front of the model: the pin block, the SubagentStart
injection, MCP search and briefing, the gate (retrieval filters on `status='active'`, and `_settle` drops conflicts
that are no longer active), and the advisor and extractor inputs. None shows a superseded statement unmarked except
one. When a rule denied a subagent's call and was superseded before the Agent call returned, the lead's handoff
read `- D-0001 (1x denied): Use PostgreSQL ...` under "Check whether it worked around them", which pushes the lead
to bring back the old rule. The line now ends with `[now superseded, no longer binding; replaced by D-0002]`.
Dropped from the proposal: "replaces X" lines across the pin block. The plugin never shows the old and new
statements together, and `audit.stale_resurrected_candidates` is already measuring whether a compaction summary
revives an old value. That warning waits for a nonzero rate.
