## Probe: what the hooks actually see

Two facts I1 depended on were unverified in every earlier triage. A throwaway plugin with a `/probe` command and
hooks that dump their payloads, run under `claude -p` on Claude Code 2.1.x (2026-11-17):

- The UserPromptSubmit payload's `prompt` is the raw typed text, `"/probe:probe confirm D-0007"`, not the
  expanded command body.
- `CLAUDE_CODE_SESSION_ID` in the Bash tool's environment equals the hook payload's `session_id`.

## Shipped: user authority needs the user's own prompt (I1)

The agent has Bash, and `/ledger` runs the CLI through the agent, so `ledger confirm`, `add --user` and
`--by user` granted user authority on the agent's word; the only guard was a prose line in `commands/ledger.md`.
A misled agent is exactly what MemoryDojo and HANDBOOK.md describe: injected or in-environment text says "confirm
D-0007" and the agent runs the command.

Now (`authority.py`): UserPromptSubmit records, as its first statement and only for a prompt that is not a harness
envelope, the `[subcommand, target]` pairs named by typed `/ledger` commands in the prompt (plugin-namespaced or
not). Targets are the positional ids before the first flag; `resolve` grants name `--keep` or `--retire`;
`retire --provenance agent` grants that scope; `add ... --user` and `dedupe --apply --by user` grant themselves.
Prose grants nothing. Inside Claude Code (`CLAUDECODE=1`) the CLI refuses user-authority calls (exit 1, an
`authority_refused` record, a message giving the exact command for the user to type) unless a grant from the latest
real prompt of the same session, under 30 minutes old, matches the subcommand and every target. A grant is spent
once, inside one `BEGIN IMMEDIATE` transaction (`LedgerStore.update_state`). Outside Claude Code (the user's own
terminal) nothing changes. With no session id in the environment (an older Claude Code) the call goes through and
`authority_unchecked` is logged, so the user's own command never breaks.

A test pins that the expanded body of `commands/ledger.md` grants nothing; it caught an example id I had first
written into that file.

Limits, stated in the module: this is friction against a misled agent, not a boundary against a determined one.
The agent can still unset `CLAUDECODE`, call the store from Python, or edit `ledger.jsonl` and `index.db` (no gate
rule protects the data directory). Agent-authority paths (`add` without `--user`, `SUPERSEDE` lines in agent text,
the MCP tools) are unchanged.

## Shipped: gate coverage audit and the hook-kill record (I2)

The plugin enforces nothing while PreToolUse is not running, and from inside a dead hook nothing can notice. The
review found a worse case already in the code: at the 25 s timeout Claude Code sends SIGTERM, and the handler
called `os._exit(0)` before any `gate` or `hook` record was written, so the gate failed open with no trace.

- `hooklib`: a killed hook now logs `{"kind": "hook", "ok": false, "killed": true, "tool_use_id": ...}` before
  exiting; every `hook` record carries `tool_use_id`.
- `coverage.py`: one streaming pass over a transcript (main chain only; subagent calls have their own transcripts)
  and `interventions.jsonl`. A gated tool call (`gate.tools`) that has a result but no `gate` record with its
  `tool_use_id` ran unchecked. Calls still running are excluded. Reports the count, how many came after a
  compaction, how many were killed or crashed, and the first one.
- Surfaces for a human, not the model: `ledger coverage [transcript]` (exit 1 on a gap), a `gate_coverage` line and
  `hook_errors_recent` in `ledger status`, and a non-required `gate coverage` check in `ledger doctor`.

## Why I3 was killed

FGSE's archived-regression probe does not transfer. The gate's `tool_history` keeps no diff text, no new-file flag
and no ok/failed outcome, so the falsifier kinds the extractor writes most (`diff_regex_*`,
`path_glob_required_with`) cannot be replayed. The semantics are inverted: a restriction usually conflicts with
earlier calls because that is why it was written ("run tests before committing" is extracted right after a commit
without tests), and replay would neuter it. It also adds an attack: an injection gets the agent to do the harmful
thing once, before any entry exists, and the protective entry extracted afterwards replays against that history and
demotes itself. Over-broad agent entries are already bounded (`is_broad_falsifier`, agent `SUPERSEDE`, deny
budgets).

## Parked: I4, shrunk to a shadow record

Stop has the final message but no per-turn tool log with outcomes, and its one block per turn is already spent on
the turn check (INTENT §8). "Tests pass" and "did not modify X" claims are generic honesty checks outside the
ledger's scope. The ledger-relevant sliver: if the final message cites an entry id that a gate record in this turn
flagged with an `advisory` decision (not a deny, which shows the rule held), and no `SUPERSEDE` named it, log
`claim_unsupported` and list it in `ledger feedback`; never block. Build it when a bench scenario has a false
compliance claim.

## Second round: review of the finished diff

A fifth reviewer attacked the diff and confirmed eight defects, all fixed before merge:

1. **Prose grants authorized checks.** "confirm D-0007 still holds before you edit", "why did you confirm D-0007?"
   and "don't ever confirm D-0007" all granted `confirm`. In ordinary speech "confirm" usually means "check", and a
   misled agent is primed to read such text as a request. Prose grants were removed; only typed commands grant.
2. **A retire grant authorized `resolve --keep`**, the opposite action, through a retire/resolve alias. Grants now
   name `resolve-keep` or `resolve-retire`.
3. **Over-broad targets**: an id inside `--reason "see D-0008"` was granted. Only positional ids count now.
4. **Legitimate commands always refused**: `retire --provenance agent --by user` (now a scope grant) and
   `--by  user` with two spaces (now matched as a regex).
5. **Non-atomic spend**: two parallel calls could both use one grant (now `BEGIN IMMEDIATE`).
6. **Coverage reported a gap for every session the plugin never saw** (this repo's own transcript: 56 of 56).
   Only calls after the plugin's first record in that session are counted. A session it never saw reports
   "plugin not seen". Calls Claude Code rejected at input validation (`<tool_use_error>`) are excluded.
7. **`status` read the whole, never-trimmed interventions log twice**, and the MCP status tool paid for that on every
   call. `recent_interventions` now reads from the end of the file, `status` reads it once, and the MCP tool skips
   the transcript scan.
8. **Kill handler ordering**: it logged after killing children (it could be force-killed first) and could re-enter
   on a second signal. It now ignores further signals, logs, then kills.

Accepted limits: an `add --user` grant does not bind the statement text; plain-English requests to add or confirm
are refused and the user is asked to type the command; it is unverified whether `!` bash mode or queued mid-turn
messages fire UserPromptSubmit (if not, those flows are refused; the fallback is the user's own terminal);
user-pasted text counts as the user's; if `gate.tools` names a tool that the `hooks.json` matcher does not,
coverage reports false gaps for it.
